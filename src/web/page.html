Schema base

    
The tool starts from the schema built into otm_explorer.py. A sync saves a fresh copy next to the script (otm_schema_cache.json) that overrides the built-in one until you revert.

1 · Sync from your OTM instance

      
Reads real foreign keys from the Oracle data dictionary, then adds links inferred from OTM's X_GID → table X naming rule for anything without a foreign key.

      

        
        
        
        
        
        
      

      

      
See / copy the SQL used (run it yourself and import the result)
        

    

    

      
2 · Import a file

      
CSV / TSV, or the "xls" export from SQL Developer / Toad. Needs columns CHILD_TABLE, CHILD_COLUMN, PARENT_TABLE, PARENT_COLUMN (optional CONSTRAINT_NAME).

      
      
3 · Built-in starter pack

      
~70 core OTM joins (orders, shipments, stops, ship units, equipment, rates, invoices, vouchers, ref nums, statuses). Loaded automatically until you sync.

      

      

    

  







  

    

      
Environments

      

      
Passwords are never saved. The helper keeps each one in memory until you stop it, so switching back to an environment is one click (header menu).

      
All environments share one synced schema — DEV, TEST and PROD normally run the same OTM version.

    

    

      
Connect to OTM

      
Queries go through OTM's DB.XML servlet with Basic Auth. Your password stays in the memory of the small helper running on your computer — it is never saved to disk and is forgotten when you stop the helper.
